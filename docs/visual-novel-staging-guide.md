# 视觉小说档位制作指南

本指南是 [制书协议](agent-book-production-protocol.md) Step 6.6 的完整操作说明，
决策依据见 [ADR-0004](adr/0004-reading-driven-camera-and-moments.md)（镜头、调色、
关键时刻）与 [ADR-0005](adr/0005-visual-novel-presentation-profile.md)（视觉小说档位）。
协议的全部数据边界照常适用：不复制正文、只引用段落 ID、私人书只在
`books/local/` 制作且永不提交。

参考实现：`books/restaurant-demo` 的 scene_006「钥匙孔」（p0113–p0136）。动手前先读它
的 `direction.json`、`playback.json` 和 `production-notes.md` 中「视觉小说垂直切片」
一节，再在 Reader 里把这一幕从 p0112 往后翻读一遍。

## 1. 审美基准

用户做这个项目的起点是 Tsukiweb（《月姬》网页版）：演出很简单，却很有感觉。
钥匙孔切片得到的评价是“氛围感上升了一个等级，有点锈湖的味道”。这就是目标。

- **氛围先于描绘。** 声音、光线、停顿、物件、质感，比画出人物更有力。
- **文字始终是主角。** 演出为一句话加重量，从不替它说话，也不抢它的注意力。
- **默认不做角色立绘，也不画角色正脸。** 立绘会让画面重复、成本暴涨，还会挤掉
  读者的想象。人物需要“在场”时，依次考虑：物件（帽子、手、一盏灯）、剪影或
  背影、原文自己的比喻。用户明确要求之前不做立绘。
- **克制在位置，不在数量。** 视觉小说档位允许高密度，但每个演出都必须对应原文里
  真实发生的事：文字里有声音才放音效，有冲击才震屏，文字在颤抖才抖字。宁缺毋滥。
- **静默也是演出。** 一次压低的音乐、一段没有音效的空白，常比多加一层更有效。

## 2. 何时使用，怎么推进

1. **只在用户明确要求时启用**（例如“做成视觉小说版”）。否则一律保持默认的
   `immersive` 档位，只可选用 Step 6.5 的镜头与调色。
2. **先做一幕切片。** 整本书设为 `profile: "visual_novel"`，但只挑一幕按视觉小说
   密度制作。切片完成后交给用户实读，用户认可再逐幕铺开。不要一开始就为全书做
   CG 和音效。
3. **第一次交付的范围：** 按协议完成整本书的可读基线（导入、全书连续的场景划分、
   每个场景的背景与 BGM，背景可以先用占位图），再加这一幕切片。validator 要求
   场景覆盖全书，所以不能只交一幕。全书基线同样要按协议 Step 2 读正文来定，
   不能用轮换或关键词填充；长篇可以按协议的分批做法，先诚实地覆盖未读部分。
4. **挑切片的标准：** 原文里有具体的声音、动作和一个可以停留的画面，最好含一个
   情绪顶点。**优先从全书前三分之一里挑**：用户要实读切片，可能还没读过这本书，
   后段高潮会剧透。用户指定了场景时以用户为准。
5. **切片以外的场景仍守沉浸阅读的纪律。** 档位放宽的预算只为切片服务；其余场景按
   协议 Step 6.5 的克制规则自我约束（每章至多 2 个关键时刻、间隔至少 40 段等），
   即使 validator 在视觉小说档位下不会拦截。
6. **全书铺开后仍然逐幕判断**：有的场景适合对话框，有的场景就该是安静的全屏文字。

## 3. 可用的演出词汇（闭集）

这些是 Runtime 能播放的全部手段。词汇表由 schema 固定，不能自造新值。

### Direction（语义）→ Playback（执行）

| 通道 | `direction.json` | `playback.json` | 说明 |
|---|---|---|---|
| 档位 | 顶层 `profile: "visual_novel"` | — | `immersive` 档位使用下面任何一项都会被 validator 拒绝 |
| 版式 | scene `layout: "nvl" \| "adv"` | cue `layout` | `adv`：底部对话框，一次一句，逐字打出，画面不压暗 |
| 氛围 | scene `atmosphere: {particles?: "dust", flicker?: "faint" \| "unsteady"}` | cue `atmosphere: {particles, density, flicker}` | 目前粒子只有 `dust` |
| 音效 | `sounds[]: {id: sound_###, at, beat?, tags, intent}` | `sounds[]: {id, at, beat?, asset_id, gain, delay_ms?}` | 向前翻到锚点时响一次 |
| 特效 | `effects[]: {at, beat?, type, strength}` | `effects[]: {at, beat?, type, intensity, duration_ms?}` | `type`：`shake` / `pulse` / `tremble` |
| CG | `cgs[]: {id: cg_###, at, beat?, until, until_beat?, tags, intent}` | `cgs[]: {…, asset_id, transition, duration_ms}` | `at` 到 `until` 含首尾 |
| 转场 | — | 背景与 CG 的 `transition`：`cut` / `crossfade` / `iris` / `wipe` | |
| 关键时刻 | `moments[]`（ADR-0004 模板） | `moments[]` | 视觉小说档位预算更宽 |
| 仪器 | `instruments[]: {id: instrument_###, kind: "radio" \| "wind" \| "letter" \| "pianola" \| "incense", at, until, intent, extent?, states[]}` | `instruments[]: {…, placement, extent?, keys[]}` | 电台、风、信、自动钢琴与香，见下文“仪器” |
| 手势 | `gestures[]: {id: gesture_###, kind, at, beat?, intent}` | `gestures[]: {…, placement, params, sound?}` | `grind_ink` 磨墨、`press_seal` 盖印、`carve_wood` 削木、`apply_cosmetics` 上妆，见下文“手势” |
| 素材 | — | `assets.json` 类型 `cg`、`sfx` | `sfx` 不可 `loop` |

### 各手段的用法

| 手段 | 什么时候用 | 不要这样用 |
|---|---|---|
| `adv` 版式 | 对话密集、需要让画面说话的场景 | 长段叙述、心理描写 |
| `dust` 粒子 | 室内、有光束、陈旧或静止的空间 | 户外开阔场景（会像雪） |
| `flicker` | 灯光本身不稳，或气氛在逼近 | 只为“增加动感” |
| `shake` | 物理冲击：破门、撞击、爆炸 | 情绪激动但没有冲击 |
| `tremble` | 文字本身在颤抖（哆嗦、结巴、惊叫） | 普通对白 |
| `pulse` | 恐惧或紧张的顶点，常与心跳音同拍 | 连续多拍使用 |
| `iris` 转场 | 视线被吸住、“看见了什么”的瞬间 | 普通换场 |
| `wipe` 转场 | 突然切入的画面、强行闯入的意象 | 温和的过渡 |
| CG | 全书最值得停留的画面，每张对应原文一个具体意象 | 装饰性画面、角色正脸 |
| `letterbox_hold` | 与 CG 同拍，给画面加电影画幅和停顿 | — |
| 电台仪器 | 电台本身就是情节的载体：守听、调谐、呼叫、接通、断开 | 只是场景里摆着一台收音机 |
| 风向仪 | 风本身就是这一段的张力：有人在起风的海上、风暴正在逼近 | 每个刮风的段落都放；只为“有天气感” |
| 信 | 整本书就是一封信，读信本身就是情节：拆信、写信人写不下去、读完放下 | 覆盖整本书；只因为书里提到一封信 |
| 自动钢琴 | 原文正在写这台机器本身：它第一次自己弹起来、被拆开找里面的魔法、重新响起 | 每一场舞会都放；想用它“配合音乐” |
| 香 | 原文用一支香计时，满屋的人都在等它烧完：诗社限时作诗 | 每一处焚香的场面都放；只为“有古意” |
| 手势 | 原文正在写主人公亲手做一个具体的动作，而这个动作就是这一段的分量 | 为了“互动感”凑一个动作；连续几段都放 |

### 数值约定（与参考实现一致）

| 项目 | 取值 |
|---|---|
| `strength` → `intensity` | `light` 0.3，`medium` 0.6，`strong` 0.95 |
| `shake.duration_ms` | 480；`strong` 再加 220 |
| `pulse.duration_ms` | 1500；`strong` 再加 220 |
| `flicker` | `faint` 0.35，`unsteady` 0.7 |
| `dust` 的 `density` | 约 0.45 |
| CG `duration_ms` | 1300–1500 |
| 场景切换的背景 `transition` | 一般 `crossfade`，进入视觉小说场景可用 `wipe`，1400–2200ms |
| 音效 `gain` | 冲击 0.85–0.9，动物与机械 0.7–0.8，人声/低语 0.5–0.6，环境性 0.6 |
| 同拍音效的先后 | 用 `delay_ms` 排队，例如破门后 180ms 狗吠 |
| 与 CG 同拍的 `letterbox_hold` | `letterbox` 0.1，`in_ms` 1200–1400，`hold_ms` 1200–1800，`hide_chrome: true` |

## 4. 逐拍编排的方法

1. 把切片的每一段列成表：`锚点 | 原文里发生了什么（用自己的话，不抄原文） | 演出`。
   先填第二列，再决定第三列；第二列是空的，第三列也必须是空的。
2. **锚点默认用段落 ID**，不写 `beat`。只有长段落里的事件明显落在后半段时才用
   `beat`。Reader 按约 120 字把段落切成阅读拍；要知道某段有几拍、事件在第几拍，
   在 Reader 里翻到该段，看 `.reading-block` 元素的 `data-reading-beat`
   属性（形如 `2/3`）。**这个属性从 1 开始计数，而契约里的 `beat` 从 0 开始**：
   `2/3` 对应 `beat: 1`。
3. 同一拍最多 2 个音效；每种特效在同一拍最多 1 个。
4. 一次顶点通常是“CG + 黑边停顿 + 心跳音 + pulse”的组合；紧接着的一两拍可以
   用 `shake` / `tremble` 延续，然后让画面回到平静。高潮之后留出几拍没有演出的空白。
5. 用 `production-notes.md` 里的切片表记录最终编排（格式见第 9 节）。

### 画面与声音的归属

- **画面属于视角人物。** 背景和 CG 显示视角人物此刻所在的地方和看到的东西。
  对话另一方在远处（电话、电台、书信、回忆）时，不切到对方那边；对方只通过声音、
  文字和调色存在。
  如果按这条规则，某个重要的世界或地点在整本书里都不会出现在画面上，就在动笔
  前问用户：是保持只闻其声，还是在原文明确进入那一方视角的段落里让它出现。
- **画面不得早于文字揭示。** 背景、CG 与调色展示的环境信息（例如城市已成废墟）
  只能出现在原文揭示之后。揭示之前，用不透露信息的画面或更暗、更近的取景。
- **持续的声音走环境音通道，瞬间的声音走音效。** 电台底噪、风、雨这类要一直
  响着的声音登记为可循环的 `ambience` 素材，由 cue 的 `ambience` 控制；调谐的
  啸叫、摩尔斯电码、敲门这类一次性声音才是 `sfx`。`sfx` 不能循环。
- **对白不配人声。** 对白由文字承载，不给台词配人声或“说话声”音效。通讯类对话
  只在一次通话的开始和结束处放非人声的提示音（接通、断开、调谐），不要每句都放。
- **同类音效不要连着放。** 同一种声音在相邻几拍重复会立刻显得廉价。重复出现的
  母题声音（如电台的接通提示）只标记段落的起止；密集的来回对话靠环境音通道维持。
- **声音不能编造内容。** 摩尔斯电码、广播、电话录音这类“带信息的声音”只能编码
  原文明确写出的内容；原文没写就用听不出内容的节奏或噪声，绝不自拟信息。

### 仪器（ADR-0006）

仪器是画面上的一块小仪表，显示一个物件此刻的状态，并跟着环境音和音效实时抖动。
它不需要任何图片素材。目前有电台 `radio`、风 `wind`（见下文“风”）、信 `letter`（见下文“信”）、自动钢琴 `pianola`（见下文“自动钢琴”）与香 `incense`（见下文“香”）。
除电台外，每一种都是为某一本书的文本选出来的，默认只属于那本书，不要因为“正好用得上”搬到别的书里；
另一本书想用，先问用户。电台的参考实现：
`books/local/we-live-in-nanjing` 的 `scripts/radio_instrument.py`（私人书，只在本机）。

- **什么时候用**：物件的状态本身就是这一段的张力，例如通联能否接通、信号强弱。
  整段区间 `at`–`until` 从物件开始被使用到被关掉，不要覆盖整章。
- **Direction 写状态变化**：`off` / `listening` / `tuning` / `contact` /
  `transmitting` / `lost`，只写原文叙述了的变化。
- **Playback 写每一拍的读数**：
  - `frequency` 只能写原文在那一段明确给出的数字，格式如 `14.255`，单位由种类决定
    （电台是 MHz）。原文没给就省略，面板显示横杠；**绝不自拟频率**。原文逐段报出
    一串频率时，每段各放一个关键帧并加 `tuning: true`，翻页时数字会滚动过去。
  - `signal` 与 `noise` 取 0–1。原文给了信号报告（如“59”即 S9）时按它定指针，
    约 S9 = 0.8；没有依据时守听约 0.05、微弱人声 0.25–0.3、清楚的来台 0.8。
    `noise` 决定指针和波形对底噪的反应，守听时 0.6–0.75，自己发射时 0.1。
  - `tx` 只在原文写到按下发射键、指示灯亮、正在说话时为 `true`；原文写到松开
    按钮就改回 `false`。
  - 每个关键帧都带上当时的 `state`；最后一帧通常是 `off`。
- **摆放**：一般写 `placement: "auto"`，底部对话框版式时在对话框上方靠右，
  全屏文字时在右上角。CG 出现时它会自动变暗让位。
- **要配合环境音**：指针和波形靠环境音与音效驱动。仪器区间里应当有持续的
  底噪环境音（如电台底噪），否则仪表会显得僵硬。

#### 风（ADR-0008）

风向仪是仪器的第二种，显示风从哪里来、有多大。参考实现：
`books/local/the-summer-book` 的 `rework_direction.py`（私人书，只在本机）。

- **什么时候用**：风本身就是这一段的张力，例如有人在起风的海上没回来、风暴正从海面上压过来。
  一本书只放在少数这样的区间里，不要给每个刮风的段落都配一块风向仪。
- **每本书各自选择**：用户希望每本书的新手段各不相同，风向仪不要因为“正好有风”就搬到别的书里；
  另一本书想用，先问用户。
- **Direction 写状态变化**：`calm` / `breeze` / `wind` / `gale` / `storm`，只写原文叙述了的变化。
- **Playback 写每一拍的读数**：
  - `from` 是风的来向，取 `n` / `ne` / `e` / `se` / `s` / `sw` / `w` / `nw`：“西南风”就是 `sw`。
    只能写原文写明的方向（同一阵风在前文已写明也算）；原文没写就省略，面板上不画箭头。
    **绝不自拟风向。** `calm` 不能带 `from`。
  - `strength` 取 0–1，参考值：`calm` 0，`breeze` 0.25，`wind` 0.5，`gale` 0.75，`storm` 0.95。
  - `gust` 取 0–1，决定环境音的起伏让箭头摆动、刻度闪动的程度；无风为 0，阵风明显的风暴约 0.8。
- **箭头画的是风吹去的方向**，箭尾在来向一侧：西南风的箭头从左下指向右上。翻页时换向会沿近的一侧转过去，跳转时直接到位。
- **要配合环境音**：区间里应当有风声的环境音（例如屋里听见的大风、风暴），
  否则箭头和刻度会显得僵硬。无风时面板只显示一个静止的中心点，不响应声音。

#### 信（ADR-0009）

信是仪器的第三种，属于《一个陌生女人的来信》：画面上是 R. 手里的那叠信纸，左边是已经读过、
翻扣下去的，右边是还没读的，最上面一张有几行抽象的字迹（不是字）。

- **什么时候用**：读信本身就是情节的地方：拆开那封没有署名的厚信、信里写到她几乎写不下去、
  R. 读完把信放下。一本书至多 3 个区间，每个区间只覆盖这些段落前后，**不要覆盖整本书**，
  否则它就成了墙纸。
- **Direction 写状态变化**：`sealed`（没拆的厚信封）/ `reading`（在读）/
  `faltering`（字迹发抖、洇开一团墨）/ `set_down`（叠齐放下，面板变暗）。
  `faltering` 只放在原文写到写信人写不下去、手在抖、不得不停笔的段落。信一旦拆开，
  之后就不能再是 `sealed`。
- **`extent`：信的正文从哪一段到哪一段。** 写信的第一段和最后一段，是原文的事实，写在 direction，
  playback 原样照抄。几个区间共用同一个 `extent`，信纸就按整封信的进度分成左右两叠，
  而不是每个区间都从头开始。省略时，区间本身就是信的范围。
- **进度不用写。** 翻过多少信纸由 Reader 按阅读位置在 `extent` 里的比例算出：每读完十分之一，
  翻页时就有一张信纸滑到左边；跳转时直接落在对应的位置。**不显示页数，也不要在任何地方写页码。**
- **Playback 的关键帧只有 `at`、可选的 `beat` 和 `state`**，每帧重复当时的 direction 状态。
- **信不响应声音**，不需要为它配环境音。
- **验证**：从区间前两三段开始向前翻，看信封在拆信那一段变成两叠信纸；在区间里向前、向后
  翻过十分之一的边界，看信纸一张张滑过去又滑回来；跳转到区间中部，看两叠直接分好；
  `faltering` 段看字迹发抖、墨迹洇开；打开“减少动态效果”，信纸直接到位，字迹不动。

#### 自动钢琴（ADR-0010）

自动钢琴是仪器的第四种，属于《百年孤独》：一卷打孔纸带从铜质读孔条前向下走过，
下面一排十二个琴键在孔经过时自己沉下去。

- **什么时候用**：原文停下来写这台机器本身的地方：拆箱装好后第一次自己弹起来、被拆开找里面的魔法、
  重新装好又响起来。一本书至多 3 个区间；家里后来每一次跳舞、每一段有音乐的场面都**不要**放。
- **Direction 写状态变化**：`closed`（琴盖合着，不动）/ `playing`（纸带走、琴键自己动）/
  `faltering`（纸带一顿一顿、有的孔不响、有的键卡住）/ `dismantled`（纸带松垮垂出、琴键散落，什么都不动）。
  只写原文叙述了的变化。
- **Playback 的关键帧**：`at`、可选的 `beat`、`state`，以及可选的 `tempo`（0–1，纸带走多快）。
  `tempo` 只能来自原文对这段音乐的描写（慢华尔兹、欢快的曲子），原文没写就省略（按 0.5）；
  `closed` 与 `dismantled` 不能带 `tempo`。
- **纸带上的孔不用写**：Reader 用区间的 `id` 生成一卷固定的纸带，同一区间每次都一样。
  孔的排列不是乐谱，**不要试图让它对上背景音乐**。
- **它不发声，也不听声音**：音乐由背景音乐通道承担；需要琴声就按音乐的规矩选 BGM。
- **验证**：从区间前两三段开始向前翻，看琴盖在 `playing` 那一段掀开、纸带开始走、琴键跟着孔沉下；
  `faltering` 段看纸带停顿、琴键卡住；`dismantled` 段看画面完全静止；跳转进区间，琴盖直接是开的；
  打开“减少动态效果”，纸带停在原处不走。

#### 香（ADR-0011）

香是仪器的第五种，属于《红楼梦》：诗社以一支梦甜香为限，香烬未成诗者罚。画面上是一只铜香炉里
立着的一支细香，香头一点火光，香灰慢慢变长、断落，一缕烟向上袅袅，环境音起伏时像有风吹过一样摆动。

- **什么时候用**：原文明写以香计时的限时作诗。一本书至多 3 个区间，每个区间从点香（或设题）
  到香尽（或交卷）。其余焚香、礼佛、闲坐的段落**不要**放。
- **Direction 写状态变化**：`unlit`（未点）/ `burning`（在烧）/ `ember`（只剩一小截，最后一段）/
  `out`（燃尽，火光消失，最后一缕烟散去）。同一区间里只能向前，不能从 `out` 回到 `burning`，
  也不能点过又回到 `unlit`；下一场诗会用新的区间，就是新的一支香。
- **Playback 的关键帧**：`at`、可选的 `beat`、`state` 与 `burnt`（0–1，这一刻烧掉了多少）。
  - `unlit` 的 `burnt` 必须是 0；同一区间里 `burnt` 只增不减，validator 会检查。
  - 原文写了“香已燃了一半”之类，就照它定值；没写就把燃烧均匀摊在这场比试上：
    点香时 0，`ember` 约 0.8，燃尽的 `out` 为 1。原文里香是被掐灭而不是烧完的，`out` 就停在当时的值。
- **两帧之间香会自己变短**：当前关键帧是 `burning` 或 `ember` 时，Reader 按阅读位置在两帧之间
  插值，所以读者一边读，香一边烧；往回翻，香会变长回来；跳转直接落在插值后的长度。
  因此关键帧只需放在原文写到香的地方，不必逐段放。
- **要配合环境音**：烟的摆动靠环境音驱动。区间里应当有屋内的环境音（例如秋夜虫声、风过竹林），
  否则烟几乎笔直上升——静室里这也是对的，但会显得僵。
- **验证**：从区间前两三段开始向前翻，看点香那一段香头亮起、开始冒烟；向前翻几段，香明显变短、
  香灰断落；往回翻，香变长；跳到区间中部，香直接是对应的长度；`out` 那一段火光熄灭、烟散去后
  画面静止；打开“减少动态效果”，烟是一条静止的曲线，香灰不再掉落。

### 手势（ADR-0007）

手势让读者在原文写到某个动作的那一拍亲手做一次：绕着砚台转圈磨墨，或按下封印。
它不挡翻页，也不改变任何文字：读者直接翻页，动作就算完成，画面显示完成后的样子
再淡出。完整规则见 [ADR-0007](adr/0007-gesture-beats.md)。

- **什么时候用**：原文用好几句写这个动作本身（怎么磨、磨多久、盖下去），而且这个
  动作是这一幕的心。一本书里很少，一幕至多一对（例如夜里磨墨、次晨盖印）。
- **锚点放在原文开始描述这个动作的那一段**，而不是动作完成之后。validator 要求
  手势之间至少隔开本档位的关键时刻间距（视觉小说档位 8 段），不能与关键时刻同拍，
  也不能落在 CG 区间里。
- **参数只能来自原文**：
  - `grind_ink.params.direction`：原文写了“顺时针 / 逆时针”才写 `cw` / `ccw`，
    否则省略（不画提示箭头）。反方向转也照样能磨，没有对错。
  - `grind_ink.params.tone`：原文要求淡墨写 `pale`，浓墨写 `deep`，没说就省略
    （按 `normal`）。
  - `press_seal` 没有参数；印面是抽象的朱红印记，不显示任何字，即使原文写了印文。
- **`sound`**：完成时响一次的 `sfx` 素材与增益，例如盖印的一声闷响（约 0.5）。
  磨墨一般不配声音。
- **摆放**：一般写 `placement: "auto"`，底部对话框版式时在对话框上方居中，
  全屏文字时在画面下方三分之一处。
- **提示语**（“转动墨条”“按下封印”）在读者本次会话第一次完成这种手势后就不再显示。
- **验证**：从手势前两三段开始向前翻；分别试完成、直接翻页跳过、按 Enter 完成，
  以及打开“减少动态效果”（磨墨变成按一下即完成）。

#### 削木（ADR-0012）

削木是手势的第三种，属于《小李飞刀》：李寻欢在雪中的马车里用小刀雕一个木头人像。
画面上是一小块浅色木料，读者在木块上划过就是一刀，刀过之处削去一片、飞出一卷刨花；
削够了，剩下的木屑淡去，露出一个站立的人形（只有轮廓，没有脸，也没有任何细节可认出是谁）。

- **每本书各自选择**：这是为《小李飞刀》选的手段，默认不搬到别的书里；另一本书想用，先问用户。
- **什么时候用**：原文停下来写他手里的刀和木头、写人像一点点成形的那一段。一本书至多 3 处，
  通常只在开篇马车里那一次；后文再提到木像，只是提到，不要再放。锚点放在原文开始写雕刻的那一段。
- **参数只有一个，而且只能来自原文**：
  - `params.stage`：原文在这一拍把人像雕完了，写 `finish` 或省略（默认 `finish`，完成后是光滑的人形）；
    原文只写他在雕、还没雕成，写 `rough`（完成后是棱角分明的粗坯），不要让画面比原文先雕完。
  - 人像是谁、什么姿势，原文写了也**不体现在画面上**，也没有参数可写。
- **`sound`**：可选，完成时响一次的 `sfx`，例如最后一刀的轻响（约 0.35）；划动时没有循环声。
- **手感**：随便在木块上划都能削，没有对错；约 12 刀或削去六成木料就完成，读者几秒内就能做完。
  提示语是“削木”，本次会话第一次完成后不再显示。
- **验证**：从手势前两三段开始向前翻；在木块上划几刀，看刀口、刨花和人形的轮廓慢慢出现；
  划到完成，看剩下的木料淡去；再分别试直接翻页跳过（直接显示完成的人形）、按 Enter 完成，
  以及打开“减少动态效果”（按一下即完成，没有刨花）。

#### 上妆（ADR-0013）

上妆是手势的第四种，属于《生尸之死》：侦探死而复起的第二天早上，在浴室镜前给自己
上妆，好让苍白的脸看起来像活人。画面上是一块苍白、偏冷的象牙灰釉面（横向的软椭圆，
带细细的开片纹），读者用指针或手指在上面刷过，刷过的地方泛起一层柔和的暖色并留住；
刷到约六成，其余部分自己暖起来，完成后这块釉面是面板上唯一的暖色。

- **每本书各自选择**：这是为《生尸之死》选的手段，默认不搬到别的书里；另一本书想用，先问用户。
- **一本书只有一次**：validator 拒绝第二个 `apply_cosmetics`（`gesture_once_per_book`）。
  锚点放在原文开始写他对镜上妆的那一段；后文再提到妆容，只是提到，不要再放。
- **没有参数**：`params` 必须写 `{}`。颜色、质感都是这个手段自己的，不能写色值，
  也不要因为原文写了粉底的牌子或颜色去找参数——画面只表达“苍白被盖住”这件事。
- **画面不画脸**：没有眼睛、鼻子、嘴，也没有镜子和人影；釉面是瓷，不是头像。
  脸在原文里，不在画面上。
- **提示语**是“上妆”，无障碍名称是“上妆，可跳过”。界面文字不写“复活”“伪装”“掩饰死亡”之类的词，
  这些由原文去说。
- **`sound`**：可选，完成时响一次；《生尸之死》不配声音。刷动时没有循环声。
- **手感**：在釉面上随便刷都能上色，没有对错；来回刷三四笔就够六成，几秒内完成。
  提示语本次会话第一次完成后不再显示。
- **验证**：从手势前两三段开始向前翻；刷几下，看暖色留在刷过的地方、边缘柔和；刷到完成，
  看其余部分慢慢暖起来；再分别试直接翻页跳过（直接显示暖好的釉面）、按 Enter 完成，
  以及打开“减少动态效果”（按一下即完成，暖色淡入）。

## 5. 必须知道的坑

- **状态通道会一直保持。** `layout`、`atmosphere`、`grade`、`ambience` 与背景一样，
  从设置它的 cue 起一直生效，直到下一个 cue 改变它。视觉小说场景结束后的第一个 cue
  必须写回 `layout: "nvl"` 和 `atmosphere: {particles: null, density: 0, flicker: 0}`；
  只属于这一幕的环境音（如电台底噪）也要在下一场景的 cue 里换掉或写 `ambience: []`。
  否则对话框、灰尘和底噪会带进后面所有场景。
- **`isolate_line` 会把 CG 一起压黑。** 与 CG 同拍的关键时刻用 `letterbox_hold`。
- **一次性演出只在“向前翻页到达”时触发**：音效、`shake`、`pulse` 与关键时刻都是
  如此。跳转、继续阅读、往回翻都不会触发，每次阅读会话也只触发一次。这是设计，
  不是缺陷，但验证时必须从切片之前开始往后翻（见第 8 节）。
- **Direction 与 Playback 必须一一对应。** `sounds` 与 `cgs` 的 id、锚点在两边完全
  一致；`effects` 的锚点与类型一致。否则报 `*_mismatch`。
- **CG 区间不能重叠**，`until` 不能早于 `at`。
- **两份文档都要是 v2。** `direction.json` 与 `playback.json` 的 `schema_version`
  都写 2。
- **预算**（视觉小说档位）：每章至多 6 个关键时刻、间隔至少 8 段；`flash_cut`
  全书至多 3 次；镜头至多每 2 段一个。没有章节标题的书整本算一章。
- **打字效果**只在 `adv` 版式、向前翻页时出现；打字中第一次点击只补全整句。
- **`iris` / `wipe` 转场只属于视觉小说档位**，沉浸档位的书用了会被拒绝。
- **取景与余量要自查。** validator 只检查镜头缩放不超过背景的
  `min_scale_headroom`（未登记时按 1.2），不检查 `framing`。余量不足 1.3 的背景
  不要写 `close` / `detail`。

## 6. 素材

### 图片来源（背景与 CG）

**Agent 不自己生图。** 用户的做法是：Agent 写 prompt，用户交给另一个生图模型出图。
在用户出图之前，Agent 用程序绘制的占位图先把节奏跑通。背景与 CG 都遵循这一点，
除非用户明确另有安排。

### 占位图与正式图

- **尽早交出 prompt。** 场景划分和切片选定后，先把背景与 CG 的生图 prompt 交给用户，
  让用户在 Agent 做编排的同时出图。
- **切片最好用正式图评审。** 交付切片时明确告诉用户哪些画面还是占位、占位会
  低估最终氛围，并询问是等正式图到位后再实读，还是先看节奏。
- **占位背景上只用保守镜头**：`wide` / `medium`，`hold` 或 `drift`，缩放不超过
  1.05；推近与焦点等正式图到位后再做。
- **正式图到位后必须重做一遍**：重新看图标注 `focal_points`，按实际像素重填
  `min_scale_headroom`，重跑编译脚本生成 playback，再 hash-assets 与 validate。
  只替换文件而不更新这些标注，焦点和余量会悄悄失效。

### CG

- 由 Agent 写生图 prompt，用户出图。规格：16:9，至少 2560×1440，JPEG；
  与同书背景同一画风；无文字、签名、水印；默认不画人脸。
- prompt 写进该书 `production-notes.md`，每张一个代码块，文件名即最终路径。
- 用户出图前先放程序绘制的占位图（numpy + Pillow），让节奏能先跑通。参考
  `scripts/render_restaurant_cgs.py`。

### 音乐

私人书的 BGM 先查用户音乐库；库里没有时按
[音乐库文档](music-library.md)“扩充音乐库”一节，经用户同意后从网易云音乐或
Apple Music 下载。全书铺开时注意：循环很短（一分钟左右）的
曲子只适合短场景，长场景要用足够长的曲目，否则几圈之后就听得出重复。主题曲可以
刻意复用（例如每次通联都用同一首），填充性的复用要避免。

### 音效

- **适合程序合成、可直接作为正式素材的**：心跳、撞击、门响、风、沙沙声、噪声类
  环境，以及电台底噪、调谐啸叫、摩尔斯电码这类电子声。参考
  `scripts/generate_restaurant_sfx.sh`（ffmpeg `aevalsrc`）。
- **合成效果差、必须标为占位的**：动物叫声、人声、笑声、低语。
- 真实录音优先 CC0 或公有领域（OpenGameArt、Wikimedia Commons）。**下载任何文件前
  （包括音效、BGM、背景与参考图）都要先向用户列出文件名、来源页、授权和大小，
  得到同意后再下载。** 下载的原始文件
  放临时目录，只把剪辑、响度处理后的片段放进书籍目录。
- 授权优先级：CC0 / 公有领域 > CC BY > CC BY-SA。BY-SA 要署名，衍生片段也须沿用
  同一授权，使用前先问用户。
- 用户暂缓下载时，把检索到的候选（用途、来源、授权、大小）记进 `production-notes.md`，
  以后不用重找。

### 登记

- 占位素材：`license` 写 `Project asset`，`source` 写
  `Procedural placeholder, <生成脚本路径>, <日期>`，`title` 末尾加「（占位）」。
- 私人书的生成与编译脚本放在 `books/local/<book-id>/` 里，不放 `scripts/`，
  因为它们会随书目内容一起被忽略、不入 git。
- 全部素材定稿后运行 hash-assets；替换任何文件后要重新运行。

## 7. 编译 playback

目前没有自动 Compiler，由 Agent 编译：

- 为每本书写一个小的编译脚本（Python），从 direction 与一张“音效 → 素材、增益、
  延迟”的映射表生成 playback 的 `sounds`、`effects`、`cgs`，数值按第 3 节约定换算。
  不要手工逐条改 JSON。私人书的脚本放在书籍目录里，方便以后重跑。参考实现是
  一次性生成的，没有保留编译脚本，新书不要照此办理。
- **脚本必须与当前数据一致。** 素材换成正式版、登记信息改了、或者手工修过某个
  JSON 之后，要同步改回生成脚本；否则下次重跑脚本会把新数据覆盖回旧状态。
  重跑前先备份 JSON，重跑后逐项对比差异，只接受预期内的变化。
- 受 git 跟踪的书要保持 JSON 的既有格式（短数组写在一行），避免产生大片无意义的
  diff；私人书不受此限。

## 8. 验证

在真实 Reader 中实际翻读，结构校验通过不等于体验通过。

1. 运行校验（本机没有 `just` 时用括号里的等价命令）：
   - `just hash-assets books/<path>`
     （`uv run --project pipeline --frozen immersive-reader-hash-assets books/<path>`）
   - `just validate books/<path>`
     （`uv run --project pipeline --frozen immersive-reader-validate books/<path>`）
   - `just validate-local`
     （`uv run --project pipeline --frozen immersive-reader-validate-library books/library.local.json`）
2. **从切片之前开始往后翻。** 一次性演出不响应跳转。在浏览器里：
   1. 先备份用户状态：localStorage 里所有包含 `<book_id>` 的键，以及全局设置键
      `immersive-reader:settings:v1`（测试“减少动态效果”时会改动它）；
   2. 把 `immersive-reader:<book_id>:revision-<rev>` 设为切片前两三段的段落 ID，
      `immersive-reader:<book_id>:reading-beat:revision-<rev>` 设为 `0`；
   3. 刷新页面，点「继续阅读」，然后逐页向前翻。
3. 逐拍确认：
   - 版式在该进时进、该退时退，灰尘和闪烁只在该场景出现；
   - 打字进行中第一次点击补全整句，第二次才翻页；
   - 每个音效都响了，包括带 `delay_ms` 的（可在网络请求或 Performance 里看
     `/sfx/` 文件是否被请求）；快速连续翻页时延迟音效也不能被吞掉；
   - CG 进出场时机正确，对话框不遮住 CG 的关键内容；
   - 往回翻不重放音效和特效；
   - 打开「减少动态效果」后，只剩音效、CG 与版式，没有打字、粒子、闪烁、震屏
     和抖字。
4. **控制台必须干净。** 开发服务器热更新后可能残留 “change in the order of Hooks”
   之类的旧错误；整页刷新后重新走一遍切片，以此时的控制台为准。
5. **收尾时恢复用户状态**：把备份的阅读进度和设置写回 localStorage。

## 10. 不在制书范围内的事

制书 Agent 只生产数据与素材，**不修改 Reader Runtime、`contracts/` 或 validator**。
如果一本书需要现有词汇之外的演出（例如电台和风以外的仪器种类、磨墨与盖印以外的手势、给人声加滤波、
说话人名牌、新的粒子种类、角色立绘），把需求和理由写进 `production-notes.md` 并告诉用户，
由用户决定是否另开一项 Runtime 工作（需要新的 ADR）。在此之前，用现有词汇里
最接近的手段表达，并在记录中说明差距。
