# Phase 4 体验闸门

> 状态：进行中  
> 负责人：项目维护者  
> 最近更新：2026-08-20

## 结论先行

Phase 4 不验证“界面是否漂亮”，而是验证沉浸演出是否帮助阅读，以及哪些
规则应进入 Phase 5 的 Matcher 和 Playback Compiler。

进入自动化阶段前需要完成至少 5 次完整阅读观察，其中至少 3 名体验者此前
没有使用过本项目。当前已有一次项目维护者的探索性体验和两条已修复反馈，
但尚不能代替完整观察。

## 体验目标

每次观察需要回答四个问题：

1. 体验者能否不经解释完成阅读？
2. 背景、音乐和环境音是在增强情境，还是在争夺注意力？
3. 文字累积、自动滚动和清屏是否保持了阅读连续性？
4. 哪些演出规则值得固化为自动编排约束？

本阶段不比较 AI 模型，不评价自动分场，也不新增与体验验证无关的功能。

## 单次观察流程

建议每次预留 15–20 分钟。

### 1. 准备

- 使用桌面浏览器打开 Reader；
- 选择“从头开始”；
- 使用默认字号、音量和动态设置；
- 不提前讲解快捷键，只告知“请按你觉得自然的方式读完”；
- 观察者不要在阅读中解释设计意图。

### 2. 静默观察

只记录可观察行为，不立即追问原因：

- 首次推进使用了点击、空格还是按钮；
- 是否出现停顿、误操作或不知道如何继续；
- 是否手动滚动、返回、打开历史或调整设置；
- 是否在某个背景、音乐、环境音或清屏节点明显分心；
- 是否静音、启用纯净阅读或减少动态；
- 是否完整读完。

### 3. 阅读后访谈

按顺序询问，避免先暗示“沉浸感”：

1. 整体读起来怎么样？
2. 有没有哪一刻让你从故事里跳出来？
3. 背景、音乐、环境音分别有什么帮助或干扰？
4. 新文字出现的位置、旧文字的明暗和清屏节奏怎么样？
5. 如果继续用它读另一篇小说，你最希望保留什么、减弱什么、去掉什么？
6. 普通阅读和这个版本，你会在什么情况下选择其中一个？

### 4. 记录

复制 [体验记录模板](experience-session-template.md)，每名体验者保存一份独立
记录。原话可以短句引用，但“观察事实”和“观察者解释”必须分开。

## 已确认的演出规则

这些规则已有直接体验证据，后续实现不得无意回退：

| 规则 | 状态 | 理由 |
|---|---|---|
| 当前段落底边停靠在窗口约 77% 位置 | 保留 | 避免进入底部渐隐区，并保留下一段生长空间 |
| 旧段落降低强调、当前段落保持纯白 | 暂时保留 | 当前反馈认为阅读舒适，仍需首次体验者验证对比度 |
| 阅读历史只包含已读内容 | 保留 | 允许回顾且不提前暴露正文 |
| 回看历史不覆盖最远阅读进度 | 保留 | 回顾行为不应破坏恢复位置 |
| 场景边界与清屏独立 | 暂时保留 | 当前 Demo 未出现阻断反馈，仍需逐场景观察 |

## 待验证的演出预算

以下是观察时重点验证的候选值，不是最终结论：

| 项目 | 当前候选 | 需要观察的信号 |
|---|---|---|
| 背景 crossfade | 1.4–2.2 秒 | 是否注意到切换本身而中断阅读 |
| BGM 默认音量 | 总音量 90%，音乐通道 55% | 是否主动调低或静音，是否盖过内在阅读声音 |
| 环境音默认音量 | 总音量 90%，环境通道 50% | 是否能感知但不抢注意力 |
| 背景保持 | 原则上至少一个语义场景 | 是否出现“像 MV 一样频繁换画面” |
| BGM 保持 | 可以跨越多个相邻场景 | 情绪变化是否足以支撑换曲 |
| 页面失焦 | 250ms 内降到轨道音量 35%，返回时恢复，不重置曲目 | 是否仍过响；切回页面时是否突兀 |

## 进入 Phase 5 的条件

只有同时满足以下条件，才开始 TXT Importer、Matcher 和 Compiler：

- 完成样本要求；
- 多数体验者认为至少一种沉浸增强有价值；
- 多数体验者不认为演出显著拖慢或打断阅读；
- 所有高影响反馈已经修复，或有明确拒绝理由；
- 背景、BGM、环境音和清屏都有可执行的保持与切换默认值；
- 纯净阅读仍然完整可用。
