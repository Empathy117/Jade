# Agent 沉浸阅读制书协议

> 触发语：**把这本 TXT / EPUB 制作为沉浸阅读版本。**
>
> 适用范围：将一份有权在本地处理的 TXT 或 EPUB 制作为可由 Reader Runtime 直接
> 打开的书籍包。协议首先服务个人阅读，同时产出未来无人值守自动化可复用的
> 标准数据。

## 1. 完成结果

Agent 必须交付一个注册到书库的完整目录：

```text
books/<book-path>/
├── source.txt / source.epub
├── source.json
├── source-assets/          # 可选；EPUB 原书附图
├── guide.json              # 可选；正文起点与常用资料图
├── codex.json              # 可选；档案：人物、关系、谱系、地点、地图
├── codex-assets/           # 可选；档案地图 SVG 等
├── direction.json
├── assets.json
├── playback.json
├── production-notes.md
└── assets/
    ├── backgrounds/
    ├── music/
    └── ambience/
```

完成后，用户打开 Reader 书库即可选择该书，不需要手改代码或 JSON。

## 2. 用户输入与默认值

最低输入只有一份 TXT 或 EPUB。以下内容如果用户没有指定，Agent 直接使用默认值，
不要用非关键问题阻塞制作：

| 项目 | 默认值 |
|---|---|
| 语言 | 从正文判断；中文默认 `zh-CN` |
| 标题 | TXT 第一个非空文本块；EPUB package metadata |
| 视觉 | 无人物立绘、背景偏写实文学插画、同书风格统一 |
| 演出密度 | 克制；地点稳定优先于情绪换图 |
| 音乐 | 悦耳、可持续循环、低音量，允许跨场景保持 |
| 环境音 | 可选且偶发，不用环境音替代音乐 |
| 动效 | 背景与 BGM crossfade，避免频繁清屏 |
| 素材策略 | 优先复用适合的已授权素材；缺失时再生成或下载 |
| 原书附图 | Importer 支持的附图保留在正文锚点；只把需反复查阅的图加入资料图册 |
| 前置内容 | 原样保留；必要时用 `guide.json.start_at` 指定默认正文起点 |
| 档案 | 人物或地理复杂到读者会回查的书才做；默认登场人物表级别（身份 + 关系 + 状态时间线），事实条目从简，结局级信息一律不入档 |

开始前只确认真正会改变整本书方向的事项，例如用户指定了完全不同的画风、
禁止联网、必须使用其私人素材，或原文件的处理权不明确。

## 3. 不可违反的数据边界

1. `source.txt` 或 `source.epub` 保存输入原始字节，任何生产步骤都不得重写。
2. 只有 Importer 可以生成 `source.json` 和 paragraph ID。经用户明确授权，且能
   逐份证明某个 EPUB spine 文档只是下载站广告、募捐页或获取渠道推广页时，
   Importer 可以不把该文档编入 `source.json`；原始文档仍须原封不动保留在
   `source.epub`。版权页、献词、目录、作者/译者前后记、正文附录和原书插图
   永远不适用此例外。
3. `direction.json`、`assets.json`、`playback.json` 禁止复制或改写正文。
4. Director 只描述语义；素材清单只描述资源；Playback 只描述执行决定。
5. 背景、音乐、环境音是三条独立状态通道。
6. 每个派生文件必须引用同一个 `book_id`、revision 和 source SHA-256。
7. Agent 的自由推理不得成为 Runtime 的隐式依赖；所有播放决定必须落盘。
8. `source-assets/` 属于原书，不属于 `assets/` 演出素材；不得裁切、调色或替换。
9. `guide.json` 只引用 source paragraph / illustration ID，不复制正文、不复制图片。
10. `codex.json` 的每个原子都携带正文首次揭示处的段落锚点，先于锚点不得暴露；
    结局级信息（真凶、诡计、终局身份）即使锚在揭露章之后也不写入。
    `codex-assets/` 属档案层，不属 `assets/` 演出素材，也不属 source 层。

## 4. 标准生产流程

### Step 0 — 预检

- 确认 TXT / EPUB 路径、书名和用户的视觉/音乐偏好；
- 检查仓库是否有未提交的用户修改，避免覆盖；
- 为书籍确定稳定的 ASCII `book_id` 与目录名；
- 确认素材仅用于用户授权的本地阅读范围。

### Step 1 — 冻结原文

使用生产 Importer，不自行解析并重写 TXT 或 EPUB：

```sh
just import-book path/to/book.epub books/<book-path> <book-id>
```

TXT 检查编码和空行分段；EPUB 检查 package metadata、spine 顺序、XHTML
文本块与正文引用的栅格附图。两种格式都要检查标题、段落数量、chapter heading
和题记分类。原书附图属于 source 层，必须保留哈希与正文锚点，不得当成背景素材。
Importer 报告冲突时
不得强制覆盖，应使用新 revision 或新目录并向用户说明。

若 EPUB 把第三方下载站广告或募捐页混入线性 spine，先逐份打开核实，再在用户
明确授权后用 repeatable `--epub-skip-document <archive-path>` 排除。必须在
`production-notes.md` 记录被排除的 archive path、判定依据和用户授权；不得按
关键词批量猜测，也不得借此删除任何书籍自身的前置或后置内容。

Importer 完成后必须人工核对一次 source 层：

- 对照 EPUB 阅读顺序抽查开头、章节边界和结尾，确认没有漏章或顺序颠倒；
- 列出 `source.json.illustrations`，逐张打开 `source-assets/` 文件，确认不是空白、
  损坏、错图或被误识别的封面装饰；
- 检查每张图的 `at` 是否落在正确标题、图注或相邻正文段落；
- 记录段落数、附图数、source SHA-256，后续文件全部引用同一 source identity。

### Step 1.5 — 可选 Reader Guide

如果一本书存在会反复查阅的人物关系图、地图、时间线或平面图，可增加
`guide.json`，只把这些关键图选入资料图册；不要把封面、装饰图等所有图片无差别
塞入图册。推理书的资料图按正文锚点随进度解锁，避免提前展示未来信息。

需要保留版权页、目录或人物表但不宜默认播放时，可把第一个叙事段落写入
`start_at`。这个选择只改变默认入口，不删除前置内容；封面必须仍提供“查看前置
内容”。`start_at` 之前但应在开篇可用的关系图，其 anchor 必须不晚于
`start_at`，这样进入正文时即可解锁。

```json
{
  "schema_version": 1,
  "book_id": "example-book",
  "source_revision": 1,
  "source_sha256": "<复制 source.json.source.sha256>",
  "start_at": "p0114",
  "references": [
    {
      "id": "ref_family_tree",
      "illustration_id": "ill0001",
      "title": "家族谱系图",
      "note": "人物关系速查；不得写入尚未揭示的身份或结局。"
    }
  ]
}
```

guide 的选择规则：

- “读者是否可能主动回来查第二次”是进入图册的判断标准；
- 标题和 note 只能描述当前已知用途，不得补充后文揭晓的信息；
- 普通插画即使不进图册，也必须在原锚点正常显示；
- 没有合适资料图、没有需要跳过的前置内容时，不创建空 `guide.json`。

### Step 1.6 — 可选档案（codex.json）

如果一本书的人物或地理关系复杂到读者会反复回查（家族小说、推理小说、
群像戏），可增加 `codex.json`，让 Reader 出现「档案」面板：交互谱系图、
可缩放地图与人物 / 地点卡。契约见 `contracts/codex.schema.json`，设计依据
见 `docs/codex-module-design.md`。编写规则不可违反：

1. **正文没说的，档案不说。** 每个原子（人物、别名、事实、关系、状态、
   地点、整张地图）都锚在正文首次揭示处；档案内容不得先于其锚点暴露。
   不写推断，不写元信息（“此人可疑”本身就是剧透）。
2. 以前置内容（登场人物表、卷首谱系图）为骨架：人物 `role` 直接沿用
   登场人物表的原文措辞；谱系图上出现的结构性关系统一锚在谱系图段落。
3. 状态变化（死亡 / 再生 / 失踪）必须逐条在正文中核实锚点；凶手身份、
   诡计说明等结局级信息不入档，即使锚在揭露章之后。
4. 地点 id 尽量沿用 `direction.json` 的 location 标签，「你在这里」与
   地点卡的已读场景列表由此免费获得；房间可挂 `parent` 形成层级，
   未入图的房间会自动高亮其所在建筑。
5. 地图重绘必须忠实原图的布局与全部标注（存疑的字样记入
   production-notes）；有原扫描图时 `source_illustration_id` 必填，
   地图 `at` 与原图锚点一致，尊重原书的信息节奏。图像放在
   `codex-assets/`，不进 Director 素材目录。**原书没有图**的书也可以
   重构示意图：图题必须标明「示意」，`at` 选正文整体揭示布局的段落
   （游园、命名、演说一类），重构依据逐条记入 production-notes；
   图上只标注正文出现过的名称，不确定的方位取其大概而不编造细节。
6. 谱系图为手排行列格：列为半格单位（一个节点占两列），夫妻相邻两列，
   子女落在父母中点所在列；不做自动布局。
7. 在真实 Reader 中验证：解锁顺序、谱系徽记、你在这里、跳转回原文、
   地图缩放、以及「查看原书扫描」回到图册出处。

### Step 2 — 导演分析

阅读带 ID 的 `source.json`，生成 `direction.json`：

- scene 必须连续覆盖所有非标题正文，无遗漏、无重叠；
- 场景边界以地点、时间、叙事阶段的真实变化为主；
- mood、tension、location、time、weather 只使用当前段落已经揭示的信息；
- 背景标签描述空间；音乐标签描述情绪和张力；环境音标签描述可听见的环境；
- 同一地点使用一致 location ID；
- 不为了增加演出数量切碎场景；
- 可给 scene 添加简短显示名称，但不得包含剧透。

### Step 3 — 素材计划

先输出场景到素材需求的清单，再开始生成或下载。逐项决定：

- 是否可以继续使用上一素材；
- 项目已有素材是否真正合适；
- 需要新背景、BGM 还是仅需环境音；
- 新素材未来是否值得进入共享素材库。

背景遵循“地点 > 时间/天气 > 情绪”；音乐遵循“情绪/张力 > 地点”；环境音
遵循“现场是否真的能听见”。一个语义场景原则上至多使用一个主背景。

### Step 4 — 获取与登记素材

- 图片：优先生成风格一致的新背景，或使用来源和授权明确的素材；
- 音乐：优先旋律完整、可长期聆听、适合循环且不会压过阅读的曲目；
- 环境音：仅在语义明确时加入；
- 下载素材优先使用作者页或官方来源，不以搜索结果页作为 source；
- 每个素材必须登记 `license`、`source`、`attribution`；不确定授权则不用；
- 同书图片保持构图、色调、时代与建筑连续性；
- 不因有新素材就强行提高切换频率。

### Step 5 — 音频处理

- 转换为浏览器稳定支持的格式；当前默认 MP3；
- 检查声道、采样率、时长、解码和文件完整性；
- BGM 做响度统一与循环接缝检查，避免首尾爆音；
- 环境音音量低于音乐，不持续占据注意力；
- 原始下载文件不直接冒充完成资产，处理过程和改动写入来源说明。

### Step 5.5 — 固定素材字节

素材属于可变的 Director 层，`assets[].sha256` 因此是可选字段。音频与图片处理
全部完成、不再打算改动之后，为整本书登记一次哈希：

```sh
just hash-assets books/<book-path>
```

此后 `just validate` 会把每个素材钉在这组字节上；任何替换或损坏都会以
`asset_hash_mismatch` 报出。若之后确实要更换素材，先替换文件再重新运行本命令。

从 `direction.json` 和最终素材生成 `playback.json`：

- 每个 cue 只引用存在的 paragraph、scene 和 asset ID；
- 只有状态发生必要变化时才写新 cue；
- 背景切换默认 1.4–2.2 秒；BGM 可以使用更长 crossfade；
- 保持仍然合适的素材，避免只因匹配度略高就切换；
- 清屏与换场独立，只有文字积累或叙事断点确实需要时才清屏；
- 没有合适素材时使用 `null` 或保持上一状态，不凑合选择；
- 音乐是常规情绪层，环境音/SFX 是少量强调层。

### Step 7 — 校验与实际体验

至少完成：

```sh
just hash-assets books/<book-path>
just validate books/<book-path>
just validate-library
just check
```

然后在真实 Reader 中检查封面、开始/继续阅读、场景切换、音乐循环、环境音、
清屏、历史跳转、纯净阅读和读完状态。结构校验通过不等于审美验收通过。

若存在 source illustrations 或 guide，还必须检查：

- 无进度时主按钮是否从 `start_at` 开始，“查看前置内容”是否从第一可读段开始；
- 每张原书附图是否在正确正文锚点显示，文字和图片都未被裁切或暗化；
- 图册初始只出现已解锁项目，读过下一张图的 anchor 后才增加对应项目；
- 单图与多图布局、缩略图切换、放大、关闭和“回到原文位置”都可用；
- 图册、历史和设置菜单不会互相叠加，浏览器控制台没有资源加载错误。

若存在 codex，还必须按 Step 1.6 第 7 条在真实 Reader 中验证档案面板，
并至少在开局、中段、读完三个进度点各检查一次解锁集合：早期不出现
后文才揭示的人物、关系、状态与标记；人物入树的位置本身也不得剧透
（例如把后文才成婚的人预先排在配偶身旁）。

### Step 8 — 注册书库

先判断版权状态，再决定书籍归属：

- **公有领域**的书可以加入受 git 跟踪的 `books/library.json`，捆绑目录放在
  `books/<book-id>/`；
- **其余一切书籍**（在版权期内、授权不明、或纯私人内容）必须制作在
  `books/local/<book-id>/`，注册进 `books/library.local.json`。这两个路径已被
  `.gitignore` 排除，任何情况下都不得提交或推送。

两个书库使用同一 schema；Reader 启动时自动合并。无论哪个书库，条目的标题、
作者、摘要、封面、revision、段落数和 production mode 都必须与 `source.json`
及实际封面文件一致。校验私有书架用 `just validate-local`。

### Step 9 — 记录人工介入

在 `production-notes.md` 记录：

- Agent 自动完成的步骤；
- 用户明确选择或修改的步骤；
- 找不到合适素材的地方；
- 原书附图数量、进入资料图册的筛选理由，以及默认正文起点；
- 若有档案：入册范围与颗粒度的取舍、剧透线的划法、锚点的核实方式，
  以及示意地图的重构依据；
- 需要反复试听或看图才能决定的地方；
- 若再做一本书，哪些动作可以安全自动化。

同一种人工判断在三本或更多书中反复出现时，才进入 Matcher、Compiler 或
其他自动化组件的候选清单。

## 5. 制作完成定义

只有同时满足以下条件才算完成：

- 原始 TXT / EPUB 哈希可验证，paragraph ID 稳定；
- scene 连续覆盖正文且没有未来信息泄露；
- 所有引用和文件通过 validator；
- 所有素材拥有可追溯授权信息；
- 背景、音乐、环境音职责分离且切换克制；
- Reader 可从书库进入、恢复进度并读完整本；
- EPUB 原书附图在正文位置可见，guide 选中的资料图可回看且不会提前解锁；
- 若有 codex：每个原子的锚点经正文核实，交叉校验通过，档案面板在
  多个进度点验证过解锁顺序且无任何形式的提前暴露；
- `production-notes.md` 已记录人工介入；
- 相关改动以原子 Git 提交保存。

## 6. Agent 交付摘要格式

Agent 完成后向用户报告：

1. 书名、段落数、原书附图数、场景数和 cue 数；
2. 新增与复用的背景、音乐、环境音数量，资料图册项目数；若有档案，
   报告人物、关系、谱系树、地点与地图数量；
3. 素材授权和无法完全验证的风险；
4. 实际播放与自动测试结果；若有 guide，说明默认起点和解锁顺序验收；
5. 仍需用户试听或判断的具体位置；
6. 本次人工介入，以及建议自动化或继续保留人工判断的部分；
7. 对应 Git 提交。
